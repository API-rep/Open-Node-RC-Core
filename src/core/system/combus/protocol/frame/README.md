# The Data Frame

This folder turns the state of the ComBus into bytes, and back. The codec is pure: it knows nothing of the state of the link, of its loss, or of any particular channel. The run level and the failsafe travel in it as ordinary channels.

## The Format

A frame is a short header, the channel bits, and a checksum. The header announces how many analog and digital channels follow, so that every link carries its own set without a fixed layout. The exact layout is described in [`combus_frame.h`](combus_frame.h).

What the format guarantees:

- **A frame fits in 255 bytes**: its length is announced in one byte.
- **A CRC-16 closes every frame**: a frame damaged on the way is dropped, before any of its values reaches the bus.
- **The frame counter never takes the value 0**: it is kept for the other kinds of frames.

## Telling Frames Apart

All frames start with the same header, so the [handshake](../handshake/README.md) and the [coupling](../coupling/README.md) frames travel on the same link as the data. The frame counter tells them apart: 0 for a handshake or, with its flag, a coupling frame; any other value for a data frame. Each kind goes to its own decoder.

## Finding Frames in the Bytes

A port only delivers bytes: the reception looks for the start byte of a frame, reads the sizes it announces, and checks its CRC. The start byte can also appear inside the data. When what follows does not make a valid frame, the reception drops a single byte and searches again, so that a false start never swallows the good frame behind it.

## Which Channels Travel

A frame carries no names, only values in a row: both ends must read the same ComBus channel at the same place. How depends on what the two ends share:

- **The same channels**, such as two boards of a node: the builder numbers them the same way on both sides, so the place in the row is simply the number of the channel.
- **Different channels**, such as a remote and its machine, or a truck and its trailer: the numbers differ from one side to the other. The link then has a table (`ComPeerLink`), generated by the builder, which gives for each place the local channel, and whether this node receives or sends it.

Either way, the [handshake](../handshake/README.md) proves that both ends agree: they compare the MD5 of this set of channels.

## The Path of a Frame

```text
          SENDING                      RECEIVING

            bus                         ComPort
             │                             │
             ▼                             ▼
   combus_frame_encode()         combus_frame_decode()
             │                             │
             ▼                             ▼
          ComPort                snapshot of the link
                                           │
                                           ▼
                                 combus_frame_apply()
                                           │
                                           ▼
                                          bus
```

- **`combus_frame_encode()`** reads the bus, through the table of the link when there is one.
- **`combus_frame_decode()`** validates first, and only then writes the snapshot of the link (its last valid frame): a refused frame leaves it untouched. The result stays indexed by place in the row.
- **`combus_frame_apply()`** writes to the bus only the channels this node receives: with a table, the table says so; without a table, the direction of the channel on this kind of link (`ChanFlow`).

**A command source** is the exception to `combus_frame_apply()`. A machine may take its commands from several sources, such as its remote or a controller plugged into it. If each link's source wrote its frames to the bus, they would overwrite each other's commands. So the link of a command source writes nothing: its frames stay in the snapshot, and [its module](../../../input/~README.md) writes them when allowed by the source manager: only one at a time.
